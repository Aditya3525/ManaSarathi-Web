Lesson 1: The Request-Response Lifecycle

Welcome to Lesson 1! Since your main goal is to be ready for external examiners, we are starting with their absolute favorite topic: "Walk me through what happens when a client sends a request to your server."

1. The Architecture in One Diagram

Here is how the ManaSarathi backend is structured. A request doesn't go straight to your database; it passes through a series of checkpoints:

[Client (Frontend)] 
      ↓ HTTP Request (e.g. POST /api/mood)
[Express Web Server (server.ts)]
      ↓
[Middleware Checkpoints] ── (Helmet, CORS, Rate Limiters, JWT Auth)
      ↓
[Routes Router (routes/mood.ts)]
      ↓
[Controller (controllers/moodController.ts)]
      ↓
[Database/AI Services] ── (Prisma Client & LLM Services)
      ↓
[Database (PostgreSQL) / External LLM API]

2. Step-by-Step Request Lifecycle

Step A: The Entry Point

When the Express server runs, the entry point is server.ts. It starts listening on port 5000 and registers all global middlewares and route files.

Step B: The Middleware Gauntlet

Before hitting any database or business logic, the request goes through middleware. Middlewares check the following:

  • Is the source allowed? (CORS)
  • Is the request safe? (Helmet security headers, Input Sanitization)
  • Is the user sending too many requests? (Rate Limiting)
  • Is the user logged in? (Authentication Middleware - checks JWT token)

Step C: Routing

If the request is safe and the user is authenticated, the router in routes/mood.ts routes it to the specific action:

router.post('/', authenticate, logMood);

Step D: The Controller & Service

The controller (e.g. logMood in moodController.ts) acts as the brain. It:

  1. Validates the input structure using schemas (Joi/Zod).
  2. Talks to the DB service (Prisma) to save the data.
  3. Sends back a neat JSON response (like 201 Created).

💡 Examiner Tip: If the examiner asks, "Why use middleware instead of checking auth in the controller?", your answer should be: "Separation of concerns. We don't want to duplicate authentication logic in every controller. Middlewares reject invalid requests early, saving server resources."

🧠 Active Recall Practice (Desirable Difficulty)

Question 1: The Lifecycle Order

Without scrolling up, try to write down or speak aloud the 5 main stages a request goes through when hitting the ManaSarathi backend.

Answer:

  1. Client/Frontend (HTTP Request)
  2. Express Server (Entry Point: server.ts)
  3. Middleware (CORS, Rate Limiting, JWT Verification)
  4. Router (Mapping endpoints in routes/)
  5. Controller & Database Services (Business logic & Prisma DB operations)

Question 2: Entry point vs Controllers

What is the difference between server.ts and a file inside the controllers/ directory?

Answer:

  • server.ts sets up the server, global middleware, databases connection, and links top-level API routes (e.g., binds all /api/mood URLs to the mood router).
  • A controller file (e.g. moodController.ts) contains the actual business logic for handling requests, such as verifying input data, creating DB records, and returning responses.
