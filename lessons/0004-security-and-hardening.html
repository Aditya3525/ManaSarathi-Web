Lesson 4: Backend Security & Hardening

Welcome to Lesson 4! In any health-related project, data security is paramount. Examiners will look to grill you on security: "How do you protect patient data? What happens if someone intercepts the traffic? How do you prevent XSS/SQL Injection?"

Let's look at the multiple layers of security built into the ManaSarathi backend.

1. Authentication & Auto-JWT Refresh

We authenticate requests using JSON Web Tokens (JWT) inside the Authorization: Bearer header. To prevent attackers from using stolen tokens forever, our JWTs have a short expiry period.

However, to avoid forcing the user to log out mid-use, we implemented a custom auto-refresh middleware: jwtRefresh.ts. If the user sends a request and their token is close to expiring, the server generates a new token and attaches it to the response via the custom header X-New-Token. The frontend reads this header and swaps the token seamlessly.

2. HTTP Headers & Helmet

We use Helmet middleware to secure Express by setting various HTTP headers. In server.ts:

app.use(helmet({
  contentSecurityPolicy: { ... },
  hsts: { maxAge: 31536000 } // Forces HTTPS for 1 year
}));
  • HSTS (HTTP Strict Transport Security): Ensures browsers only talk to our backend over secure HTTPS, never unencrypted HTTP.
  • CSP (Content Security Policy): Directs browsers where they are allowed to download and execute scripts/images from, preventing cross-site scripting (XSS) injection.

3. CORS (Cross-Origin Resource Sharing)

By default, browsers block web pages from making requests to a different domain. We configure CORS so only our trusted frontend domain can call our backend API. If a malicious site tries to invoke our API endpoints on behalf of a user, the browser automatically blocks the request.

4. Input Sanitization & SQL Injection Prevention

  • SQL Injection: Since we use Prisma ORM, SQL injection is prevented out-of-the-box. Prisma parameterizes all queries (using prepared statements), meaning user input is never executed as SQL code directly.
  • XSS Sanitization: Our custom sanitization.ts middleware scans the request body and strips out dangerous HTML tags (like <script>) before they reach the controllers or database.
💡 Examiner Tip: If the examiner asks, "How do you protect your API endpoints from being flooded by hackers or automated bots (DDoS)?", your answer should be: "We implemented two levels of rate-limiting: a global rate limiter of 500 requests per 15 minutes, and custom, tighter rate limiters (e.g., in authRateLimits.ts) on authentication endpoints like login, registration, and password reset to block brute-force attacks."

🧠 Active Recall Practice (Desirable Difficulty)

Question 1: Preventing SQL Injection

How does our backend prevent SQL Injection? Do we manually clean SQL query strings?

Answer: No, we don't manually clean query strings. We use Prisma ORM, which automatically parameterizes all queries. This ensures that user input is treated strictly as data parameters, not executable SQL command strings.

Question 2: JWT Auto-Refresh

Explain why we use short-lived JWTs combined with an auto-refresh middleware instead of just issuing tokens that last for 1 year.

Answer: Long-lived tokens (e.g. 1 year) are a major security risk: if a token is stolen, the attacker has permanent access. Short-lived tokens minimize this risk window. The auto-refresh middleware solves the UX problem: as long as the user is actively using the app, they receive new tokens automatically without being logged out.
