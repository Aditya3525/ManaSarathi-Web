Lesson 2: Database Schema & Relationships

Welcome to Lesson 2! In project evaluations, teachers love to test your database knowledge. They will ask questions like: "Explain your database schema," "What is Prisma?" and "Show me how tables are related."

1. What is Prisma ORM?

Prisma is an ORM (Object-Relational Mapper). It lets you write JavaScript/TypeScript code to interact with your database instead of writing raw SQL queries. You define your schema in schema.prisma, and Prisma automatically maps it to your PostgreSQL or SQLite database.

2. Understanding Schema Relationships

Your database models are connected. Let's look at the three main types of relationships in ManaSarathi:

A. One-to-Many Relationship (1 : N)

A single User can log their mood multiple times. So, one User maps to many MoodEntry records.

[User Table] 1 ─────── 🔗 ─────── 0..* [MoodEntry Table]

In schema.prisma, this relationship is defined like this:

model User {
  id          String      @id @default(cuid())
  moodEntries MoodEntry[] // One user can have many mood entries
}

model MoodEntry {
  id        String   @id @default(cuid())
  userId    String   // Foreign Key: links back to User
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
}

B. One-to-One Relationship (1 : 1)

A user has exactly one mental health safety plan. One User maps to exactly one SafetyPlan.

[User Table] 1 ─────── 🔗 ─────── 1 [SafetyPlan Table]

In Prisma, we write this by adding @unique on the foreign key field:

model User {
  id         String      @id @default(cuid())
  safetyPlan SafetyPlan? // Optional 1:1 relation
}

model SafetyPlan {
  id         String   @id @default(cuid())
  userId     String   @unique // @unique makes it a 1:1 relationship!
  user       User     @relation(fields: [userId], references: [id])
}

C. Cascading Deletes (onDelete: Cascade)

Notice the onDelete: Cascade in the relations. This is a critical security and cleanup setting. If a user deletes their account, all of their related mood entries, journal logs, and chat histories are **automatically deleted** by the database. No orphan records are left behind.

💡 Examiner Tip: If the examiner asks: "What happens to the user's assessments if you delete the user from the database?" Your answer should be: "They are automatically deleted due to the onDelete: Cascade rule set up in our Prisma schema. This ensures data integrity and respects user privacy laws (GDPR/consent requirements)."

🧠 Active Recall Practice (Desirable Difficulty)

Question 1: Defining 1-to-1 in Prisma

How do we tell Prisma that a relationship is 1-to-1 instead of 1-to-many?

Answer: By applying the @unique attribute to the foreign key field (e.g. userId String @unique) in the child table. Without @unique, it would default to a one-to-many relationship.

Question 2: Cascade Deletes

Why do we use onDelete: Cascade in a mental wellness app?

Answer: It ensures that when a user deletes their profile, all their sensitive data (journals, assessments, moods) is wiped immediately from the database to maintain data privacy compliance, prevent orphan records, and save space.
