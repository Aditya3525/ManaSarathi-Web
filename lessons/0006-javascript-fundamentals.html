Lesson 6: JavaScript Core Fundamentals

Welcome to step 1! To write backend code, we must master the primary language: **JavaScript**. Today we cover the modern ES6 features that you will see on every line of the backend.

1. Variable Scopes: let vs const

In modern JavaScript, we never use var. We use:

  • const: For values that won't be reassigned. (Default to this!).
  • let: For variables that can change.
const PORT = 5000;
// PORT = 6000; // ❌ TypeError: Assignment to constant variable.

let requestCount = 0;
requestCount++; // ✅ Allowed

2. Arrow Functions

Instead of the old function keyword, modern code uses arrow functions. They are shorter and handle scopes better:

// Old way:
function add(a, b) {
  return a + b;
}

// Modern Arrow Function:
const add = (a, b) => a + b; // implicit return (no curly braces needed)

// Multi-line Arrow Function:
const greetUser = (name) => {
  const message = `Hello, ${name}!`;
  return message; // explicit return (needed when using curly braces)
};

3. Destructuring (Objects & Arrays)

Destructuring lets you extract properties from objects or values from arrays into variables quickly.

const user = { name: "Aditya", role: "Developer", age: 21 };

// Old way:
const name = user.name;
const role = user.role;

// Destructuring:
const { name, role } = user; // Instantly extracts both!

4. Template Literals

Instead of messy string concatenation with +, use backticks (`) and ${} to interpolate variables:

const mood = "Happy";
const message = `The user is feeling ${mood} today.`; // ✅ Clean!

Exercise 1: Convert to Arrow Function

Convert this old JS function into a modern arrow function using destructuring: 

function printDetails(user) {
  const name = user.name;
  console.log("User name is: " + name);
}

Solution:

const printDetails = ({ name }) => {
  console.log(`User name is: ${name}`);
};

Exercise 2: const with Objects

If we define an object with const, can we change its properties? For example: 

const config = { port: 5000 };
config.port = 6000; // Will this throw an error?

Answer: No, it will not throw an error. const prevents re-assigning the variable name itself (i.e. you cannot do config = {}), but it does not make the object properties read-only. The object can still be mutated.
